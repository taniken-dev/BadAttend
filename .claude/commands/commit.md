# /commit

変更を「目的ごと」に分けて、複数のコミットを作ります。**プッシュはしません**（プッシュは `/push`）。
BadAttend（公開リポジトリ）と BadAttend-db（非公開リポジトリ、SQL/migration専用）の両方を対象とします。

## 方針

- 1コミット = 1つの目的。後から読んで「なぜ変えたか」がわかり、そのコミットだけを `git revert` できる単位にする
- 各コミットの時点でビルドが通る状態にする（関数を消すコミットには、その呼び出し元の変更も含める）
- 目的が1つしかない変更なら、無理に分けず1コミットでよい

## 手順

### A. BadAttend（このリポジトリ、公開）

1. `git branch --show-current` を確認する。**main にいる場合は、コミットする前に止まり**、作業ブランチ（例: `feat/<内容>`）を作るかユーザーに確認する（main はプッシュすると本番にデプロイされるため）
2. `git status`、`git diff HEAD`、`git log --oneline -10` で、変更の全体と既存のメッセージスタイルを把握する
3. 変更を目的ごとのグループに分け、コミットの計画を作る。各グループについて次を決める：
   - 含めるファイル（同じファイルに複数の目的の変更が混ざる場合は、その変更箇所）
   - コミットメッセージ
   - コミットの順番（依存される側を先に。例: ライブラリ → 使う画面 → ドキュメント）
4. 計画を表でユーザーに示してから実行する（計画の確認は不要。スキル発動が承認とみなす。ただし main にいる場合は手順1に従う）
5. グループごとに、該当ファイルだけを `git add <パス>` してコミットする
   - **同じファイルに複数の目的が混ざる場合**（対話式の `git add -p` は使えない）：
     1. 最終版のファイルをスクラッチパッドに退避する
     2. 最終版から後のグループの変更を取り除いた「途中版」を作り、作業ツリーに置いてステージ・コミットする
     3. 次のグループへ進み、最後に最終版に戻す。最終版が退避したものと一致することを `diff` で確かめる
     - 分けるのが難しく、ビルドが壊れる恐れがある場合は、無理をせず1コミットにまとめ、その旨を報告する
   - 途中版をコミットする前に `npx tsc --noEmit -p .` を実行し、型エラーがないことを確かめる
6. コミットメッセージのルール：
   - プレフィックス: `feat:` / `fix:` / `refactor:` / `style:` / `docs:` / `test:` / `chore:` のいずれか
   - 1行目: 変更の「目的・理由」を日本語で簡潔に（50文字以内）
   - 本文: 変更の要点を箇条書きで列挙（必要な場合のみ）
   - フッター: 実際に作業している Claude のモデル名で `Co-Authored-By: Claude <モデル名> <noreply@anthropic.com>` を付ける（例: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`）
   - ヒアドキュメント形式（`git commit -F - <<'EOF'`）で実行する

### B. BadAttend-db（`../BadAttend-db`、非公開、SQL専用）

7. `../BadAttend-db` が存在し、変更があれば、Aと同じ方針とメッセージルールで目的ごとにコミットする（例: マイグレーション本体 と 確認用SQL は別コミット）
   - このリポジトリは main に直接コミットしてよい（SQL は自動適用されず、ユーザーが SQL Editor で実行するため）
8. 変更がなければスキップする

### C. 完了報告

9. リポジトリごとに、作成したコミットをハッシュ・メッセージの一覧で報告する
10. コミットしなかったファイル（未追跡のメモなど）があれば、そのファイルと理由を添える
11. 「プッシュはまだしていない。タスクが終わったら `/push`」と添える

## 注意事項

- 機密ファイル（`.env`, `*.key`, `*secret*` 等）、および `supabase/` 配下のSQLファイルは絶対に BadAttend へステージしない（SQL は BadAttend-db 側のみで管理）。`git add -A` / `git add .` は使わず、パスを指定してステージする
- 目的がはっきりしないファイル（ユーザーの作業メモ、`docs/tasks/` など）は勝手にコミットせず、報告してユーザーに任せる
- 既存のコミットを書き換える操作（`--amend`、rebase など）はしない
- コミットするものがない場合は「変更なし」と報告してスキップする
