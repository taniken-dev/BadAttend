# タスク04：出欠登録ルールの厳格化（締切の DB 強制・当日登録の廃止・未提出者の扱い・2週間ごとの提出）

> 共通ルール（Next.js ドキュメントの確認、SQL の置き場所、時刻の扱い、コミット方法）は [README.md](README.md) を参照。

## 背景

- 部会で「出欠アプリを今後も使っていくので、全員必ず出欠連絡をすること」「連絡しなかった人は練習に参加できなくする」と部員に告知済み。
- 今のルールでは、その週の火曜23:59が正規の締切で、それを過ぎても練習当日なら登録できる（遅延扱い）。その結果、当日に登録する人が多く、火曜までに登録する人が少ない。
- 部員には「締切（火曜）までしか登録できないようにし、当日の登録は廃止する」と予告している。
- さらに、アルバイトのシフト提出のように、**毎週の提出をやめて「2週間分をまとめて提出」する方式**に変えたい。提出の回数が減るので、提出率が上がると見込んでいる。

## 導入スケジュール（決定済み：段階導入）

| フェーズ | 開始 | 内容 |
|---------|------|------|
| **1** | **2026-09-30（水）の練習から** | 毎週の提出はそのまま。締切（火曜23:59）を DB で強制し、当日の新規登録を廃止する。未提出者の扱い（後述）を始める |
| **2** | 未定（フェーズ1の様子を見て決める） | 2週間ごとの提出に切り替える。**コードは今回実装しておき、設定を入れるまでは動かない**ようにする |

- フェーズ1の対象は 9/30〜10/2 の練習。受付は今までどおり 9/26（土）に始まり、**9/29（火）23:59 に締め切る**。
- **9/29（火）23:59 より前に、デプロイと SQL の実行を終えておく必要がある。** 間に合わない場合は、すぐにユーザーに報告する。
- 切り替え日は**コードに書かず、DB の設定テーブルに持たせる**（後述）。コードはいつプッシュしてもよく、ルールの切り替えは設定値の日付で自動的に起こる。

## 現状の仕組み（実装前に自分でもコードを読んで確認すること）

- 登録期間の計算：`src/lib/utils.ts` の `getWeeklyRegistrationInfo()`
  - 土〜火23:59：翌週（月・火は今週）の水・木・金を登録できる
  - 水〜金：受付なし
  - 2026-05 のハードコードされた特例が残っている（もう不要。削除してよい）
- 当日の登録ウィンドウ：`src/app/(dashboard)/calendar/CalendarView.tsx:1105` 付近の `isSameDayWindow`。練習当日は登録できる。当日に欠席を選ぶと `absent_emergency` になる（`:1180`）
- 登録期間外でも、登録済みの人は欠席へ変更できる（事前欠席連絡）：`CalendarView.tsx:1113` 付近の `canEarlyAbsent`
- 合宿・部会はいつでも登録できる。自主練習は別の仕組み（参加表明。開始1時間前まで）
- 実績確定の UI：`CalendarView.tsx` の 300〜450行目付近、および 2183行目付近。未提出者の実績を手動で選び、デフォルトは `absent_unreported`
- 週次リマインド：`src/app/api/cron/remind/route.ts` が未提出者へ LINE で**個別に**送っている（`vercel.json` は `0 11 * * 2`。UTC なので JST では火曜20:00）。管理者の「LINEでリマインド」ボタンも個別送信
- **登録期間は画面側でしか制御していない。** `attendance_insert_own` ポリシーは本人であることしか見ていないので（`../BadAttend-db/fix_coach_attendance_block.sql`）、API を直接叩けば期間外でも登録できる。**今回は DB で制御する。**
- **「今日」の判定がずれる不具合：**
  - `CalendarView.tsx:607` は `new Date().toISOString().split('T')[0]` で「今日」を求めている。これは UTC なので、JST の 0〜9 時は前日の日付になる。
  - `getWeeklyRegistrationInfo` と cron は、実行環境のローカル時刻で曜日を計算している（ブラウザなら JST、Vercel なら UTC）。

## 要件

### 1. 設定テーブル（`../BadAttend-db/migration_registration_policy.sql`）

- DB 側の強制とアプリの画面表示が同じ値を見るように、設定は DB に1か所だけ置く。例：

  ```sql
  CREATE TABLE public.registration_policy (
    id                boolean PRIMARY KEY DEFAULT true CHECK (id),  -- 1行だけのテーブル
    strict_start_date date,  -- フェーズ1：この日以降の練習は締切を強制し、当日登録を禁止する（NULL なら旧ルール）
    biweekly_start    date,  -- フェーズ2：2週間サイクルの基準日（月曜）。NULL なら毎週提出
    updated_at        timestamptz DEFAULT now()
  );
  INSERT INTO public.registration_policy (strict_start_date) VALUES ('2026-09-30');
  ```

- 認証済みユーザーは SELECT でき、UPDATE は admin だけにする。
- 登録期間を計算する SQL 関数を作る。例：`public.registration_window_for(session_date date) RETURNS (opens_at timestamptz, deadline timestamptz)`。JST で計算する（`AT TIME ZONE 'Asia/Tokyo'`）。

### 2. DB で登録期間を強制する（同じ migration ファイル）

- `attendance_records` への **本人による INSERT** は、そのセッションの受付期間内（`opens_at` ≦ now ≦ `deadline`）でなければ拒否する。方法は BEFORE INSERT トリガー（わかりやすいエラーメッセージを返せる）か、RLS の `WITH CHECK` で関数を呼ぶ形。
- 本人による UPDATE で締切後にしてよいのは、次の変更だけにする。
  - 欠席への変更（事前欠席・当日欠席 `absent_emergency`）
  - 遅刻への変更
  - 当日の欠席・遅刻連絡は**残す**（急な体調不良まで連絡できなくすると、かえって無連絡欠席が増えるため）
  - 締切後に「欠席 → 出席」へ変えるのを許すかは、自分で判断せずユーザーに確認する
- 対象外にするもの：
  - manager と admin による代理登録・実績確定（`result_status` の更新）
  - 合宿（`is_camp`）、部会（`is_bukai`）、自主練習（`is_voluntary`）、休止（`is_cancelled`）
  - `strict_start_date` より前の練習（旧ルールのまま。当日登録も可）
- エラーは画面にわかりやすく出す（例：「締切（9/29 23:59）を過ぎたため登録できません。欠席・遅刻の連絡のみ可能です」）。

### 3. アプリ側の登録期間の計算

- `src/lib/registration.ts` などに、**「現在時刻」と「設定」を受け取る純粋関数**として作り直す。
  - 例：`getRegistrationWindow(now: Date, policy: RegistrationPolicy)`
  - 曜日と日付は実行環境のタイムゾーンに依存させず、**必ず JST で判定する**（保存は UTC のまま。README の時刻ルールを参照）。
- DB の関数と**同じ結果になる**ことを、テストか確認スクリプトで保証する。
- `CalendarView` と cron の両方でこの関数を使う。`CalendarView.tsx:607` などで「今日」を UTC で求めている箇所も直す。
- フェーズ2（`biweekly_start` が設定されている場合）の仕様：
  - `biweekly_start`（月曜）から2週間ごとにサイクルを区切る
  - 対象は、そのサイクルの第1週と第2週の水・木・金（6回分）
  - 受付は、サイクル開始の直前の土曜から、サイクル第1週の火曜23:59まで
  - ⚠️ 実際に切り替える前に、この仕様でよいかユーザーが最終確認する。今回は実装とテストまで行う

### 4. 未提出者の扱い（決定済み）

- **締切後の告知は、LINE の自動送信ではなく「コピー用の文章」で行う。**
  - LINE の通数は受信者の人数で数えられる。通知先のグループは部員全体（50人以上）なので、1回の自動送信で50通以上を消費する。無料枠は月200通しかない。
  - 管理者・マネージャー向けに、「締切のお知らせ文」を生成してコピーできるボタンを作る。
    - 締切前のリマインド：「◯/◯（火）23:59 締切です。未提出◯名」。名前を入れるかは任意
    - 締切後の告知：「◯/◯〜◯/◯ の出欠を締め切りました。未提出の方（◯◯、◯◯…）は練習に参加できません」
  - 管理者が LINE グループに手で貼る（人が投稿するので0通）。
  - 置き場所は、カレンダーのセッション詳細、またはホーム画面。
- **未提出者への個別の LINE 送信はやめる。**
  - `src/app/api/cron/remind/route.ts` の個別送信は、止めるか削除する。`vercel.json` の cron も合わせて外す。
  - 管理者の「LINEでリマインド」ボタンは、上のコピー用の文章に置き換える。
- **実績を確定するとき、未提出者を自動で `absent_unreported` にする。**
  - 管理者が1人ずつ選ばなくても、「確定」操作で未提出者全員に `status = 'absent_unreported', result_status = 'absent_unreported'` の行が作られるようにする。
  - 個別に変更（例：実は来ていた）できる手段は残す。
- 本人の画面では、締切後に登録ボタンを押せない状態にし、「締切を過ぎたため登録できません」と表示する。

### 5. ドキュメントの更新

- `/rules`（`src/app/(dashboard)/rules/page.tsx`）の登録期間の説明を、新しいルールに書き換える。`strict_start_date` と `biweekly_start` の設定に合わせて文言を切り替える。
- README.md の「当日登録ウィンドウ」「週次自動リマインド」「未提出者へのLINE個別リマインド」などの記述を更新する（`/readme` スキル）。
- 部員向け・マネージャー向け・管理者向けマニュアル（`docs/*.docx`。`docs/generate_manuals.py` で生成）で更新が必要な箇所を一覧にし、ユーザーに報告する（今回はマニュアル自体の更新はしない）。
